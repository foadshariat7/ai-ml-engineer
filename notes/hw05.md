This document explains what is required in [`hw05.py`](hw05.py). For each of
the six functions, write its time complexity, its auxiliary space complexity,
and a short comment explaining why — and only then run the code.

Answer from the code itself rather than from memory: read what each line
actually does, and do not assume a one-line function is cheap.

## What to write for each function

Under every function there is an answer stub. Fill in each line:

```python
# Time:
# Space:
# Why:
```

- **Time** — how the number of operations grows as the input grows.
- **Space** — the *auxiliary* space only: memory the function allocates
  itself, not the memory the input already occupies.
- **Why** — one or two sentences naming the operation responsible for the
  cost.

<div dir="rtl" align="right">

## برای هر تابع چه بنویسید

زیر هر تابع جای پاسخ آماده است. هر خط را کامل کنید:

- **Time** — تعداد عملیات با بزرگ‌شدن ورودی چگونه رشد می‌کند.
- **Space** — تنها فضای *کمکی*: حافظه‌ای که خودِ تابع تخصیص می‌دهد، نه
  حافظه‌ای که ورودی از پیش اشغال کرده است.
- **Why** — یک یا دو جمله که عملیاتِ مسئولِ آن هزینه را نام ببرد.

## The functions

### 1. `get_last(numbers)`

Returns the last element. Ask whether the length of `numbers` changes the
amount of work.

### 2. `contains(numbers, target)`

A linear scan with an early `return`. This is the one function whose best case
and worst case differ, so the stub asks for both. Say where `target` sits in
each case, and which of the two Big O normally reports.

### 3. `combinations(numbers)`

Two loops over the same input. Decide whether they are sequential or nested
before you write anything — that single distinction decides the answer.

### 4. `double_values(numbers)`

A list comprehension. Consider both the work done per element and the list
that is built and returned.

### 5. `unique_values(numbers)`

Builds a set from the input. A single set lookup is O(1) on average — but this
function is not a single lookup.

### 6. `sorted_values(numbers)`

Calls `sorted()`. One line of code is not evidence of constant time; state
what CPython's sort actually costs, and whether `sorted()` allocates.

## General rules

- Write every answer **before** running the file.
- Give the simplified Big O form: drop constants and dominated terms, so
  `O(2n)` is written `O(n)`.
- Report time and auxiliary space separately — they are often different.
- State what `n` refers to in each function.
- The calls at the bottom of the file are commented out. Uncomment them only
  after your answers are written, then check your predictions against what
  actually runs.

<div dir="rtl" align="right">

## قوانین کلی

- همه‌ی پاسخ‌ها را **پیش از** اجرای فایل بنویسید.
- شکل ساده‌شده‌ی Big O را بنویسید: ضرایب ثابت و جمله‌های مغلوب را حذف کنید،
  پس `O(2n)` را `O(n)` بنویسید.
- زمان و فضای کمکی را جداگانه گزارش کنید — این دو اغلب متفاوت‌اند.
- مشخص کنید که `n` در هر تابع به چه چیزی اشاره دارد.
- فراخوانی‌های انتهای فایل کامنت شده‌اند. تنها پس از نوشتن پاسخ‌ها آن‌ها را از

## Complexity questions

Answer these after the six functions, in the comment block at the end of the
file:

- What does `n` represent in each function?
- Which functions return a new collection, and what does that cost in space?
- Which function has a different best case and worst case, and why?
- Is a list comprehension a different complexity class than the equivalent
  loop?
- Why is `set(numbers)` not O(1), even though a single lookup is O(1) on
  average?
- Why is `sorted(numbers)` not O(n), even though it is written on one line?
- Which of these functions mutate their input?
